<h2>Speed should be visible</h2>
<p>Users do not care that the implementation is clever. They care that the page loads fast, feels responsive, and never makes them wait on obvious actions.</p>
<p>That means performance work should start with the actual interaction model of the page: what loads first, what blocks the message, what shifts after render, and what JavaScript is doing work the server could handle.</p>
<h2>The biggest wins are usually simple</h2>
<ol>
  <li>Keep as much UI server-rendered as possible.</li>
  <li>Push expensive visuals behind intent or scroll.</li>
  <li>Ship lighter image assets and size them correctly.</li>
  <li>Trim animation and effects that compete with content.</li>
  <li>Measure actual user experience, not only local lab scores.</li>
</ol>
<h2>What we optimize for</h2>
<p>The most useful metric is whether the page feels premium quickly. If the message is visible, the interaction is stable, and the path to action is obvious, then the performance work is doing the right job.</p>
